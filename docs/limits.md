# 上限在哪里

这份文档回答一个问题:在这块 Pi 4(BCM2711,4× Cortex-A72,8GB)上,大模型推理最快能到多少,是什么在限制它。

所有数字都是在本机实测的。测量时芯片没有主动散热,温度 83–86°C,处于降频状态,所以绝对值偏低;结论中的相对关系不受影响。

## 三个上限

| 上限 | 实测值 | 怎么测的 |
|---|---|---|
| 内存带宽 | 约 3.1–3.6 GB/s | `bench/limits` 的 `read` 行,数据远大于缓存 |
| CPU 运算 | 每核约 2.5 GB/s(Q4_0 权重) | `bench/cycles`,硬件计数器读周期数 |
| 散热 | 满载时主频 1.53–1.63 GHz,标称 1.8 GHz | 运行中采样 `vcgencmd measure_clock arm` |

### 内存带宽

- 只做"读出来异或一下"这种最便宜的操作,一个线程就能达到 3.1–3.6 GB/s。
- 加线程不会增加:2、3、4 个线程合计仍是 3 GB/s 左右,有时更低。
- 提前 0.5–4 KB 做软件预取,能再提高 10–30%。
- 一个线程同时读多条独立的数据流会变慢(4 条流约 2.5 GB/s)。
- 引擎里对比过几种预取方式(1.5B 模型,2 线程):预取后四行 2.74–2.87 token/s,不预取 2.45,按固定距离预取每条流 2.50–2.61,预取到二级缓存 2.31。现在用的是第一种。
- LPDDR4-3200 接口的理论峰值是 12.8 GB/s,实测只有它的四分之一左右。差距出在 SoC 内部,具体原因没有查证,软件能做的只有预取。

### CPU 运算

A72 是 ARMv8.0,没有 SDOT 点积指令,8 位乘法要用 `smlal` 先扩展到 16 位。

| 运算核 | 每个权重块的周期数 | 1.8 GHz 下单核速度 |
|---|---|---|
| Q4_0,一次一行 | 17.4 | 1.9 GB/s |
| Q4_0,一次四行 | 11.3 | 2.9 GB/s |
| Q8_0,一次一行 | 17.6 | 3.5 GB/s |
| Q8_0,一次四行 | 11.6 | 5.3 GB/s |

一个 Q4_0 权重块是 18 字节,Q8_0 是 34 字节。

四行运算核每个块仍要 11 个周期,每周期只执行约 1.3 条指令。把乘法全部换成加法,周期数几乎不变,所以瓶颈不在乘法器。真正的原因还没找到,这是一个待研究项。

### 散热

没有风扇时,空闲温度就在 75°C 左右,满载几秒内到 85°C,固件把主频压低 10–15%。这只影响卡在 CPU 上的部分。

## 哪个上限起作用

取决于在做什么。

**逐个生成 token:卡在内存。** 每生成一个 token,所有权重都要从内存读一遍。单核的运算速度和内存带宽差不多,所以两个线程就把内存占满,第三、第四个核帮不上忙,还会因为争抢而变慢。

**读提示词:卡在 CPU。** 一批 16 个 token 一起过每个矩阵,权重只读一遍、用 16 次,内存不再是瓶颈,四个核都有用。

以 qwen2.5-0.5b-instruct-q4_0 为例:

| 部分 | 每个 token 读的字节 |
|---|---|
| 24 层的权重(Q4_0) | 201 MB |
| 输出层(Q8_0,151936 × 896) | 145 MB |
| 合计 | 346 MB |

按 3.3 GB/s 算,生成速度的上限是 9.5 token/s。目前实测 7.0 token/s,是上限的 74%。

**4 个线程读提示词只比 2 个快一点,原因在环境。** 3B 模型上,前馈层每核吞吐从单线程的 2.3 GB/s 掉到 4 线程的 1.1 GB/s。同样的下降在完全不出缓存的 `bench/limits` L1 测试里也出现,所以和批处理的写法无关:桌面应用长期占着约一个核,4 个核全开时芯片更热、主频更低。绑核(`OMP_PROC_BIND`)和忙等(`OMP_WAIT_POLICY=active`)都试过,没有改善。

## 怎样超过这个上限

带宽不能改,能改的是每个 token 要读多少字节,以及怎样把空闲的核用起来。

1. **输出层两段式计算**:输出层占了 42% 的读取量,但最后只需要概率最高的几十个 token。先用一个小得多的近似矩阵筛出候选,再只对候选用原矩阵精确计算。
2. **推测解码**:用空闲的核提前猜后面几个 token,一次批量验证。猜对的 token 不需要单独再读一遍权重,输出结果不变。
3. **更低位数的量化**:读取量和速度成反比,但会改变模型输出。
4. **散热和超频**:只对卡在 CPU 上的部分(读提示词)有效。

## 复现

```
make
bench/limits            # 内存和 CPU 的吞吐量,约 1 分钟
taskset -c 3 bench/cycles   # 每个权重块的周期数
```
